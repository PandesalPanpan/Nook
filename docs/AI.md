# Optional AI

AI is Off by default and has no capture/startup dependency. Settings supports Off, OpenAI, DeepSeek and a custom OpenAI-compatible chat-completions endpoint. Keys/configuration are account-scoped device settings: browser localStorage on web and AES-256-GCM preferences with an Android Keystore key on Android. Android ciphertext is authenticated against its account ID. Keys never enter Room/Dexie records, sync outboxes or ZIP exports. Saving Off removes the account's key. Guest-to-cloud record merge does not migrate AI credentials; configure the provider separately in the destination account.

Only an explicit request sends content. Inbox requests send the saved capture and up to 100 active Project/Area/Resource titles/IDs. Note summarization sends its saved body. Project/task breakdown sends its saved title/outcome. Unsaved editor drafts and attachment originals are not sent. The UI explains the recipient before requesting. Configuration uses HTTPS without URL credentials/query parameters; requests refuse redirects. Custom browser endpoints must allow the app origin and Authorization/Content-Type headers through CORS.

Providers implement a separate `AiProvider` interface. Current adapters use JSON-mode Chat Completions, strict response validation, a 45-second timeout and a 100 KB response cap. Requests accept up to 20,000 text characters. Responses allow at most 12 next actions and 12,000 summary characters. Off performs no network call. Provider response/error bodies are never displayed or logged; errors contain no raw response, key or endpoint credentials. Active requests cancel when their UI/account/source changes. No AI request runs in the background.

Suggestions remain transient proposals. A destination proposal shows the actual local destination and explanation; Move as note processes the capture locally and associates the new note with that destination, preserving originals. Breakdown lets the user select actions; confirmation creates only selected project tasks or subtasks. A summary confirmation creates a new linked note and preserves the source body. Every accepted change uses the ordinary local-first repository/outbox transaction. Source and destination versions, deleted/archive state and account identity are rechecked before committing. Stable proposal-derived IDs reject repeated acceptance and roll back partially duplicated action batches.

The defaults are `gpt-4o-mini` at the OpenAI chat-completions endpoint and `deepseek-flash` at the DeepSeek endpoint. Models are editable; select one that supports JSON Chat Completions. OpenAI uses `store:false` and `max_completion_tokens`; DeepSeek uses `max_tokens` and disables thinking for these short suggestions. Custom endpoints use the compatible `max_tokens` format. References: [OpenAI structured outputs / JSON mode](https://developers.openai.com/api/docs/guides/structured-outputs), [DeepSeek JSON output](https://api-docs.deepseek.com/guides/json_mode/), [DeepSeek Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/), [Android Keystore AES-GCM](https://developer.android.com/reference/android/security/keystore/KeyGenParameterSpec).

Verification covers all three enabled adapters against controlled successful/error responses, Off inactivity, unknown destinations, incomplete responses, HTTPS enforcement, credential/error isolation, transaction rollback, stale/deleted/account guards, preserved originals and non-destructive summaries. The browser flow intercepts the provider HTTP request, confirms nothing is written before acceptance, selects one action, confirms/reopens its saved task, and clears the key with Off. Android instrumentation uses the real device Keystore to verify encrypted persistence and rejection of ciphertext copied to another account. Its real Compose confirmation flow uses a fake provider and verifies selected local writes.

No live billable provider credentials have been supplied or used.
