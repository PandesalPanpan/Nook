==================================================
PRODUCT
==================================================

Name: Nook

Purpose:
A very fast, calm, offline-first personal operating system / second brain using PARA principles.

Primary interaction:
Capture first → clarify later → organize → act → archive.

The user should NEVER have to choose a folder/type before quickly saving a thought.

Core principles:
1. Capture must be extremely fast.
2. Device-local database is the immediate source of truth.
3. Firebase is synchronization, not the primary runtime database.
4. Nook must remain useful with airplane mode enabled.
5. Use smart defaults and progressive disclosure following “Don’t Make Me Think”.
6. PARA should be taught contextually rather than through a giant tutorial.
7. AI only suggests actions; it must never silently reorganize user data.
8. Avoid guilt-driven productivity UX, punishment streaks, or noisy dashboards.
9. Android integration is a first-class feature, not an afterthought.
10. Web should be designed for desktop rather than simply stretching the mobile UI.

==================================================
OFFLINE-FIRST ARCHITECTURE
==================================================

This is extremely important.

ANDROID:
UI
→ repository/domain layer
→ Room
→ durable sync outbox
→ Firebase

WEB:
UI
→ repository/domain layer
→ Dexie / IndexedDB
→ durable sync outbox
→ Firebase

Every normal mutation must:
1. write locally first,
2. immediately update the UI,
3. enqueue the remote operation,
4. sync asynchronously when connectivity exists.

The app must not block normal use while waiting for Firebase.

Implement:
- durable outbox
- retry/backoff
- tombstones for deletions
- schema versioning
- updatedAt timestamps
- createdAt
- device/client IDs as appropriate
- account isolation
- safe sign-out
- conflict handling

For normal same-record conflicts, a deterministic last-write-wins strategy is acceptable for V1, but document it clearly.

Deleting something offline must NOT cause it to reappear when another client reconnects.

==================================================
LOCAL-ONLY MODE
==================================================

Nook must work without an account.

Default onboarding should allow:
“Use Nook without an account”

Local-only users get the complete core application except cross-device cloud sync.

Later they can enable Firebase sync.

When a local user signs in:
- safely merge/upload existing local data
- do not replace the local database with an empty cloud account
- prevent duplicate imports as much as reasonably possible

Do not reuse any unrelated Firebase project from other applications.

If Firebase credentials/project provisioning are unavailable, implement the entire local architecture and Firebase integration/emulator/config templates anyway, then report the exact external configuration still needed.
